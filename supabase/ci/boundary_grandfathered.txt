# Specification v1.2 §16.2: "A migration that adds a callable function must
# register it and pass the boundary assertion in the same migration, so an
# ungoverned entry point cannot survive its own transaction."
#
# Every file below predates that discipline — they are the dashboard-named
# migrations of 29 and 30 August, and a migration is written once, so they
# cannot be corrected in place. They are listed here rather than the check
# being softened, because a rule with a visible list of exceptions is a rule,
# and a rule with a lowered bar is not.
#
# This is NOT a claim that those migrations left an ungoverned door behind.
# erp.assert_public_api_safe() runs on every build against the whole schema and
# is green: no ungoverned entry point exists today. What was missing is the
# guarantee that one could not survive its own transaction in future, which is
# what supabase/ci/boundary_in_migration.sh now enforces for everything after
# this list.
#
# Nothing may be added to this list. A new migration that needs to be here is a
# new migration that should call the assertion instead.
